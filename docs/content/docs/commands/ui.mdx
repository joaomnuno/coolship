title: ui
description: Open a full-screen menu with the application's status and every verb.
---

<Callout type="warn" title="Experimental">
`coolship ui` is a draft to learn whether a menu earns its place. Its keys and layout may change in any release, and it may be removed.
</Callout>

```text
coolship ui [flags]
```

`ui` opens a full-screen menu. At the top is the linked application: its name, environment, project, and context, its status, and its last deployment. Below it are the verbs, in the same five groups and the same order as `coolship help`. The menu is a way to reach the verbs. A verb chosen here runs exactly as it would if you had typed it.

```text
coolship ui  experimental
coolship-example  production · project coolship-example · context home
● running:healthy  https://coolship.example.com
Last deployment: ✓ finished  a1b2c3d  3h ago

Get started
› login           Save a Coolify instance and API token on this machine
  init            Create a Coolify application for this repository, then link it
  link            Bind this repository to an existing Coolify application
Ship
  deploy          Deploy the linked application using its configured Coolify source
  preview…        Deploy the preview Coolify holds for a pull request
```

The header is read in the background, behind a spinner, so the menu can be used straight away. It is read again every five seconds, and `r` reads it at once. In a directory that is not linked, the header says `not linked` and the menu still offers `link` and `init`.

## Keys

| Key                     | Does                                                          |
| ----------------------- | ------------------------------------------------------------- |
| `↑` `↓`, `k` `j`        | Move                                                          |
| Typing, or `/`          | Filter the verbs by name; Backspace edits, Esc clears         |
| Enter                   | Close the menu and run the verb                               |
| `r`                     | Read the header again                                         |
| Esc, `q`, Ctrl-C        | Leave without running anything                                |

While a filter is being typed, `j`, `k`, `q`, and `r` are part of the filter.

## Running a verb

Enter closes the menu and restores the terminal first. The verb then runs in the same process with the global flags `ui` was given, such as `--context`, `-e`, `--target`, `--verbose`, or `--format json`, so its output is what the command prints on its own.

A verb that cannot run without a value ends in `…` and asks for it before running:

- `preview` asks for the pull request number (`--pr`).
- `domain set` asks for one or more domains, separated by spaces; a bare host means `https`, and a Compose application takes `SERVICE=URL` pairs.
- `logout` asks for the context to remove.
- `config get` asks for the preference key, and `config set` for the key and its value.

Esc at that prompt goes back to the menu, and Ctrl-C leaves without running anything. An answer that starts with a dash is passed as a value, never as a flag. Arguments that are optional, such as the deployment UUID of `cancel` or the command after `dev --`, are not asked for; run those commands directly to pass them.

The menu lists `env pull`, `env diff`, and `env push` rather than `env`, which only prints help. `help` and `completion` are not listed.

## Terminal

`ui` needs a terminal on both stdin and stdout, and it does not open in CI, where Coolship asks nothing even if the job attaches a pseudo-terminal. Without one it exits with code `2` and suggests `coolship help`. While the menu is open, request lines from `--verbose` and `--debug` are held back so they do not draw over it; the chosen verb runs at the verbosity you asked for.

## Exit codes

`0` when the menu is left without choosing; otherwise the chosen verb's own exit code. `2` when stdin or stdout is not a terminal, and in CI.
