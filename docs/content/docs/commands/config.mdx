title: config
description: Show the effective configuration for this directory, and read or change your preferences.
---

```text
coolship config [flags]
coolship config show [flags]
coolship config get KEY
coolship config set KEY VALUE
```

In a terminal, `config` opens a form. At the top it shows this directory's binding, where credentials come from, the instance, and the preferences file. None of that can be edited there, and no token is ever shown. Below are your [preferences](#preferences): `verbosity`, `build_logs`, `color`, `hints`, and `update_check`. Left and right change a value, Enter moves to the next one, and Shift+Tab goes back. Save writes only the keys you changed to `preferences.toml`, Discard leaves it as it was, and Esc leaves without writing and exits `130`.

```text
$ coolship config
Coolship preferences
Binding:      Personal / production / fenix-bot
Credentials:  /home/you/.config/coolify/config.json
Instance:     home at https://coolify.example.com
Preferences:  /home/you/.config/coolship/preferences.toml (absent; saving creates it)
┃ verbosity
┃ Default output detail when neither --verbose nor --debug is given
┃ ← normal →

  build_logs
  Stream build logs during a deployment; auto follows the verbosity
  auto
  …
```

When stdout is piped, with `--format json`, or when input is not a terminal, `config` prints the same view as `config show`, so scripts see no change.

## config show

`config show` shows the discovered configuration file, the selected target, the binding, which credentials would be used, and the preferences file, after applying any overrides. It reads files only: no request is made to Coolify and no token is shown.

```text
$ coolship config show --context home
Configuration:    /home/you/my-app/coolship.toml
Git root:         /home/you/my-app
Target:           default
Application root: /home/you/my-app
Context:          home
Project:          Personal
Environment:      production
Application:      fenix-bot
Credentials:      /home/you/.config/coolify/config.json
Instance:         home at https://coolify.example.com
Preferences:      /home/you/.config/coolship/preferences.toml (absent)
Override context: home
```

Use it to see what `--cwd`, `--config`, `--context`, `--environment`, and `--target` resolve to, or which of the committed context and the `COOLSHIP_URL`/`COOLSHIP_TOKEN` pair applies.

## config get and config set

`config get KEY` prints the value in effect for one preference and nothing else, so a script can read it with `$(coolship config get verbosity)`. A key the file does not set prints its default. `config set KEY VALUE` writes one key. Like `gh config set`, it prints nothing on success when output is piped; in a terminal, one confirmation line goes to stderr.

```bash
coolship config get verbosity          # normal
coolship config set verbosity verbose
coolship config set build_logs auto    # removes the key
coolship config set hints false
coolship config get hints --format json
```

`set` creates the file and its directory when they are absent, with modes `0600` and `0700`. Every other line in the file, comments included, is kept, and a changed key keeps its place and its trailing comment. The new file replaces the old one in a single rename, so no reader ever sees half a file. When the file already has a problem elsewhere, such as an unknown key, nothing is written and the error names the problem.

An unknown key or a value outside the key's list exits `2` and names the keys or values, with the closest key when the name looks like a typo:

```text
$ coolship config get colour
Error: unknown preference "colour" (did you mean "color"?); the keys are verbosity, build_logs, color, hints, update_check
```

## Preferences

Preferences are one developer's tastes on one machine, as opposed to the configuration in `coolship.toml`, which the team shares and commits. They live in a TOML file that Coolship reads on every command and writes only through `config set` and the `config` form:

- Unix and macOS: `~/.config/coolship/preferences.toml`, or `$XDG_CONFIG_HOME/coolship/preferences.toml` when `XDG_CONFIG_HOME` is an absolute path
- Windows: `%AppData%\coolship\preferences.toml`
- Anywhere: the file `COOLSHIP_PREFERENCES` names, for tests and CI

```toml
verbosity = "normal"   # normal | verbose | debug
build_logs = true      # true streams build logs, false collapses them; absent follows the verbosity
color = "auto"         # auto | always | never
hints = true           # false turns off hints, the questions after them, and fix-it offers
update_check = true    # false turns off the daily check for a newer release
```

| Key            | Values                           | Default  |
| -------------- | -------------------------------- | -------- |
| `verbosity`    | `normal`, `verbose`, `debug`     | `normal` |
| `build_logs`   | `auto`, `true`, `false`          | `auto`   |
| `color`        | `auto`, `always`, `never`        | `auto`   |
| `hints`        | `true`, `false`                  | `true`   |
| `update_check` | `true`, `false`                  | `true`   |

`verbosity` is the default when neither `--verbose`, `--debug`, nor `COOLSHIP_VERBOSITY` is given (see [verbosity](/docs/platform/output#verbosity)), and `build_logs` decides the build log when neither `--logs` nor `--no-logs` is given; `auto` means the key is absent and the verbosity decides. `color` is read and checked today and takes effect in a later version. `hints = false` turns off the next-step hints after a command, the questions that follow them, and the offers to fix a failed command. `update_check = false` turns off the [update notice](#update-notice). Credentials never go in this file: the Coolify URL and token stay in [Coolify CLI's file](/docs/concepts/credentials), so one login serves both tools.

The `Preferences` line of `config show` shows the path, then `(absent)` when there is no file or the keys it sets, such as `(verbosity verbose, build logs off, color auto)`. An unknown key, a value outside its list, or a file that cannot be read is warned about once at the start of every command and the file is ignored; the line then says `(ignored: …)` with the reason. A broken file never stops a deploy.

## Update notice

Once a day, a released build of Coolship asks GitHub for the latest release, ignoring pre-releases, while the command runs. The check gives up after two seconds and never holds up the command: if the command finishes first, the check is abandoned and tried again next time. When a newer release exists, one line is printed on stderr after the command's own output, at most once a day for each release:

```
A new Coolship release is available: v0.4.0 (you have v0.3.0). Upgrade: curl -fsSL https://raw.githubusercontent.com/joaomnuno/coolship/main/scripts/install.sh | sh
```

The notice only appears when stderr is a terminal. It never appears in CI (when `CI` is set), with `--format json`, or for a development build. Set `COOLSHIP_NO_UPDATE_NOTIFIER=1` or `update_check = false` in the preferences file to turn it off. The time of the last check and the release it found are kept in `state.json`, next to `preferences.toml`. Coolship writes that file itself, and it can be deleted at any time.

## JSON

`config show --format json`, and `config --format json`, print:

```json
{
  "config_path": "/home/you/my-app/coolship.toml",
  "config_root": "/home/you/my-app",
  "git_root": "/home/you/my-app",
  "target": "default",
  "app_root": "/home/you/my-app",
  "binding": {
    "context": "home",
    "project": "Personal",
    "environment": "production",
    "application": "fenix-bot",
    "root": "."
  },
  "credential_source": "file",
  "credential_path": "/home/you/.config/coolify/config.json",
  "instance": "home",
  "instance_url": "https://coolify.example.com",
  "overrides": { "context": "home" },
  "preferences": {
    "path": "/home/you/.config/coolship/preferences.toml",
    "present": true,
    "verbosity": "verbose",
    "build_logs": false
  }
}
```

`binding` is the selected table from `coolship.toml`, including any UUID pins and `dev` setting. `credential_source` is `file` when the Coolify CLI configuration supplies the credentials and reflects the environment pair when `COOLSHIP_URL` and `COOLSHIP_TOKEN` do; `git_root`, `credential_path`, `instance`, `instance_url`, `overrides`, and `warnings` are omitted when empty. `preferences` carries `path`, `present`, the keys the file sets (`verbosity`, `build_logs`, `color`, `update_check`, `hints`; an absent key is omitted), and `error` with the reason when a present file is ignored.

`config get KEY --format json` and `config set KEY VALUE --format json` print one object. `set` is `true` when the file sets the key, and `false` when the value is the default, as after `config set build_logs auto`:

```json
{ "key": "verbosity", "value": "verbose", "set": true, "path": "/home/you/.config/coolship/preferences.toml" }
```

## Exit codes

`0` when the configuration could be resolved or the preference was read or written; `1` when the preferences file could not be written; `2` when the directory is not linked (for `config show`), the file is invalid, the target is ambiguous, the credentials cannot be selected, or a preference key or value is unknown; `130` when the form is left with Esc or Ctrl-C.
