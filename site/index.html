coolship

Link once, then ship.

Coolship is a project-local CLI for Coolify. It binds the repository you are in to its Coolify application, so deploy, logs, and env work from the terminal without UUIDs or dashboard navigation.

Install

curl -fsSL https://raw.githubusercontent.com/joaomnuno/coolship/main/scripts/install.sh | sh

or go install github.com/joaomnuno/coolship@latest, or build from source with Go 1.26 or newer.

In the terminal

One deployment, observed exactly

After coolship link, no command needs a resource identifier. deploy submits one deployment and follows the UUID that submission returned, streaming the server's build log while it waits.

When something is off, doctor runs every step a command performs and reports each one.

Commands

What it does

Everything reads the binding that link wrote. Every command takes --format json; results go to stdout, progress and prompts to stderr.

link
Bind the repository to an existing Coolify application and write a credential-free coolship.toml; it never creates remote resources.
status
Report the linked application's current status and URL.
deploy
Deploy from the source and branch already configured in Coolify, wait for that exact deployment, and stream its build log; --no-wait, --force, and --timeout adjust it.
logs
Read the application's runtime logs, with --follow to keep polling and --lines to choose how far back.
open
Open the application's public URL in your browser, or its Coolify page with --dashboard; --print only prints it.
doctor
Check configuration, Git boundary, binding, credentials, context, server version, and the application itself, exiting 1 when a check fails.
env pull · diff · push
Synchronize a local .env with one scope of the application's variables; withheld values are never invented, and shared references stay references.
preview
Deploy the preview Coolify already holds for a pull request, from --pr or GITHUB_REF in GitHub Actions.
dev
Run a local command with the application's runtime variables injected over your environment, exit status and Ctrl-C forwarded.
domain
Show the application's domains, and replace them with domain set, reading the application back to confirm.
targets
In a monorepo, [apps.<name>] tables are selected by the directory you are in or by name: coolship deploy api.

link writes one small, versioned file at the repository root. Commit it; tokens and secret values are never written to it.

version = 1

[project]
context = "home"
project = "Personal"
environment = "production"
application = "fenix-bot"
root = "."

Scope

How it relates to coolify-cli

Coolify already has coolify-cli, and Coolship is not meant to replace it. coolify-cli manages Coolify resources; Coolship manages the developer workflow around the project you are currently working on. Creating servers, private keys, or team members stays out of scope.

Credentials are shared: Coolship reads the contexts coolify-cli already stores in ~/.config/coolify/config.json, so if you have authenticated there, you are ready to go. In CI, COOLSHIP_URL and COOLSHIP_TOKEN stand in for it.

Verified against Coolify 4.3.18. Every command was run end to end against a live instance. The 4.3.19 source has no changes to any endpoint Coolship uses; other versions are untested. Known limits.
